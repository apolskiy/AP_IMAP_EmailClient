## Key architectural decisions

| Date | Decision | Register |
|---|---|---|
| 2026-10-26 | Packages `emi_reader`, `emi_sender`, `emi_test_broker`, `emi_greenmail`, `emi_api`, `emi_harness`; one folder, unit-test folder and CI job per tool | AMB-56, AMB-62 |
| 2026-10-26 | Stdlib `imaplib` behind a transport interface; read-only waiting by polling | AMB-09, AMB-22 |
| 2026-10-26 | Shared local test broker (port 8025) with auto-start, run leases and dated log | AMB-53, AMB-54 |
| 2026-10-26 | Settings precedence: argument > CLI > env > `.env` > default; one option table | AMB-10, AMB-11 |
| 2026-10-26 | Keyword grammar `<TOOL>_<PROTOCOL?>_<CAUSE>`, `CASE_`, `JOB_` | AMB-61, AMB-62 |
| 2026-10-26 | Functional CI on Windows and Ubuntu; P0 → P1 → P2–P4 chain; gates 100 / 100 / 85 / 95% | AMB-15, AMB-44, AMB-48 |
| 2026-10-26 | Test ID in mail is the TestRail case ID `C<number>`, so emails map to TestRail cases directly | AMB-63 |
| 2026-10-26 | New keywords: `CASE_VERIFICATION_FAILED` (false check or plain `assert`), `CASE_UNEXPECTED_ERROR` (untyped exception, class as secondary), `HARNESS_DUPLICATE_TEST_ID` (collection stops) | `docs/keywords.md` |
| 2026-10-26 | `EmiError` is a tuple of the tools' error bases: tools cannot import `emi_api`, and `except` ignores ABC virtual subclasses | Design §8.2 |
| 2026-10-26 | Sender always serializes with CRLF (`policy.SMTP`) so SMTP dot-stuffing cannot corrupt links; `max-line-length` 120 | Spike Evidence |
| 2026-10-26 | Functional suite of 1,016 cases: every parametrized case is its own TestRail case through a per-parameter `emi(case=...)` marker; a test needing several addresses uses address slots `<run>-rNN` of its own case, so no two tests share an address | Design §4, §13.3 |
| 2026-10-26 | Test validity: named faults as backend wrappers prove each functional test can fail for the right reason; stability repeats find flaky tests and thin timing margins; `CASE_NO_VERIFICATION` for a test that checks nothing; non-blocking `test-validity` job | AMB-64 |
| 2026-10-26 | CI: one reusable functional chain called per OS, so each OS keeps its own P0 → P1 → P2-P4 order; the harness exit code (2 = abort) decides whether the chain goes on; Greenmail started by one composite action on both OSes | Design §12 |
| 2026-10-26 | A P0 failure stays critical but stops nothing: the P0 job finishes, P1 and P2-P4 run, only dependents are skipped; the CI chain shares one run ID and passes earlier jobs' results on, so dependents in later jobs are skipped too | AMB-65 |
| 2026-10-27 | Test validity built and run live: all 9 named faults caught by all 47 catching tests. The runs found two harness bugs (a fault wrapper hid the broker client from `EmiApi`; a keyword enum in a test report crashed xdist workers) and two test gaps (counts and batches compared sets, so an extra email passed; `sender-drops-email` missed batches). Faults never touch the session probe | AMB-64 |
| 2026-10-27 | The gate counts a selected test without a result as not passed (`JOB_RESULT_MISSING`): a CI P2-P4 job hit its 1 h budget after 748 tests, its workers crashed on a keyword enum, the remaining tests left no result, and the gate passed at 758/759 | Design §9.7 |
| 2026-10-27 | Windows CI: Greenmail started through WMI, because a step's child process ends with the step on Windows runners | Design §12 |
| 2026-10-27 | The status workflow is `joint-ci-workflow`; a manual run ticks its functional jobs; P2, P3 and P4 run as three jobs side by side, their 85% measured together by `quality-gate` | AMB-66, AMB-67 |
| 2026-10-27 | `--priority` accepts any case, and the gate is told which jobs were chosen (`--expect`): a chosen job without a `collection.json` fails it (`JOB_RESULT_MISSING`), checked per OS. CI run 40436448076 passed the gate on 10 of 1,016 tests after its P2, P3 and P4 jobs exited on a lowercase `--priority p2` | Design §9.7 |
| 2026-10-27 | P0 is one email of each kind: activation and invitation links (C400001, C400002) and a generic email with no link (new C400006), and per link kind a wait that skips two non-matching emails for a later matching one (new C400007, C400008); the P0 report had listed a single test | AMB-68 |
| 2026-10-27 | Allure: priorities are labels (`parentSuite`, `severity`, `tag`), failure keyword families are categories; the harness verdict sets each non-passed result's status and `[KEYWORD]` message, because Allure categories match only messages and never see passed tests | AMB-69 |
| 2026-10-27 | Batch cases split across P2, P3 and P4 by seed: in runs 40437111627 and 40437565154 P2 took 16-25 min against about 4 for P3 and P4, because it sent about twice the mail and every wait searches the whole mailbox, which slows as it fills | AMB-70 |
| 2026-10-26 | Waits poll by `UID SEARCH UID <next>:*` plus the address and fetch all candidates in one command: on Greenmail a search costs about 45 ms at any size while each fetch grows with the folder (about 0.7 s at 5,000 messages); limiting the first search alone gained nothing and was dropped. One single-email wait went from 1.84-1.99 s to 1.07-1.12 s, measured back to back on the same folder | AMB-71 |
| 2026-10-26 | Job counts (selected, passed, failed, skipped, without a result) printed by the CLI and written with the not-passed tests to `GITHUB_STEP_SUMMARY`; the gate writes its report there too. Counts come from the harness results, not pytest's line, so they match the gates; a summary that cannot be written only warns | AMB-72 |
| 2026-10-26 | Network-fault unit tests marked `network` (registered in `pyproject.toml`) so their count is reproducible; README counts unit tests per tool, functional tests per family (each functional test drives all tools, so a per-tool split would be invented) | AMB-73 |
| 2026-10-26 | A failed or skipped test's emails are collected by address after the test (`POST /emails`, `api.reader.emails_to`) rather than by carrying raw bytes in every wait result and error: one lookup only on failure, covers matched, unmatched and late emails, and leaves the wait path and the fault wrappers unchanged. Collected in the call-phase report hook, because pytest-html ignores sections added at teardown | AMB-74 |
| 2026-10-26 | P0 + P1 time share: a 30% ceiling reported as `JOB_PRIORITY_TIME_SHARE`, never a gate failure (timing fails only a test, through its own limit); measured only with P2-P4 results present | AMB-75 |
| 2026-10-26 | Mailbox inventory taken from each wait's own `EXAMINE` and fetches (no extra IMAP command), because a separate lookup costs about 0.7 s per fetch at 5,000 messages | AMB-76 |
| 2026-10-26 | Fault proxy with simulated IMAP/SMTP servers in the normal unit jobs; Greenmail stop/start tests as a separate unit subset (`unittests/outage/`, `docker`) with its own Ubuntu job, outside the prioritized regression | AMB-77 |
| 2026-10-26 | Inventory carried by each `/wait` answer (read before the connection returns to the pool) and handed to `EmiApi` observers, from the answer or a failed wait's error; owned by the test its address names, so the session probe logs as `C000000`. Broker version 1.1.0, so a stale broker without `/emails` or `"inventory"` is refused instead of silently missing them. `GET /inventory` not built | AMB-76 |
| 2026-10-26 | Fault proxy built on threads with `SO_LINGER` 0 resets rather than `asyncio` (AMB-14), so a live connection can be reset from outside its loop; `once=True` faults let tests see the reconnect. Refused-port tests use a 5 s connect timeout because Windows retries a refused connect for about 2 s. Outage tests accept `SENDER_SMTP_SERVER_UNREACHABLE` beside `..._CONNECTION_REFUSED`, since Docker Desktop accepts a stopped container's port and closes it; they are not marked `network`, so `-m network` never stops Greenmail | AMB-77 |
| 2026-10-26 | Outage test 100133 found that a wait does not ride through a Greenmail restart (a refused reconnect is fatal under AMB-13); recorded as open rather than changed, since it reverses a resolved retry rule | AMB-78 |
| 2026-10-26 | AMB-78 B: a refused reconnect is retried once the wait has had a working connection, counting a mid-session drop or timeout as one, so a dead pooled connection is covered; the first connect stays fatal. Verified against a real Docker Desktop restart | AMB-78 |
| 2026-10-26 | Fault proxy `refuse` fixed for Linux (shutdown before close, `select` before `accept`) after CI run 40450901295; verified in a `python:3.14-slim` container before pushing, since no Linux host is available locally | AMB-77 |
| 2026-10-27 | `CHANGELOG.md` started, covering every commit since the first one | n/a |
| 2026-10-27 | The status workflow renamed `ci-regression-run` (from `joint-ci-workflow`), pairing with `ci-debug-run`; Markdown excluded from every CI trigger | AMB-66 |
| 2026-10-27 | A run deletes only its own mail: the server searches `HEADER X-EMI-Run-Id` for the run's timestamp (Greenmail matches by substring), and the broker keeps a UID only when its header's run (`<stamp>-<token>`, worker part dropped) equals the requested one, so a substring match never deletes another run's mail. Refused only while a lease of the same run is active, since other runs' leases cannot be affected. The stability check runs P0 to P4 as separate jobs under one run ID, each deleting its own mail, because run 40451473560's second repeat timed out at about 15,600 messages | AMB-79 |
| 2026-10-27 | One shared poller per broker serves every wait: each cycle `EXAMINE`, an address search for new waits, an `OR` search (at most 20 terms) over new UIDs for the others, and one `UID FETCH`; each wait keeps its own deadline, count and settle rules. Measured on Greenmail at 15,604 messages: every fetch about 6 s whatever its form, a search 0.05 s, 4 per-wait polls 25.7 s against one shared poll 6.1 s. The poller holds one budget slot; a wait holds none. At about 15,000 messages a new wait needs 12-15 s; recorded as a known limit rather than adding a cache, since load beyond a normal run is out of scope | AMB-80 |
| 2026-10-27 | One option table in a new package `emi_config/`, which every package may import: each tool's `settings.py` declares its rows, the tables nest (reader and sender, then broker, then API, then harness), and `merge` refuses one name declared two ways. The sender, broker and harness CLIs and the pytest plugin are generated from it, tools without a prefix (`--smtp-host`), the harness and pytest with `emi-`. Chosen so each tool works on its own with the same names, variables and defaults as the tests | AMB-81 |
| 2026-10-27 | The broker's `/health` lists each setting's source; the sources travel to an auto-started broker in its settings file and stay out of `config_hash`, so the same values from another source reuse the running broker | AMB-81, R-CFG-04 |
| 2026-10-27 | Recipient field combinations: `Fields` is one `Field` or a tuple of them; `"to,cc"`, `"cc+to"` and lists are accepted and labelled `to+cc` in the manifest and over the wire. A single field stays a plain `Field`, so existing callers and the wire format for one field are unchanged. Broker version 1.3.0 | AMB-82 |
| 2026-10-27 | 15 functional cases: each combination of `To`, `Cc` and `Bcc` for each kind, missed by a wait on a field outside it and found on each of its fields, and `Delivered-To` alone; they add 15 catches for the two field faults. The other uncovered cases are closed, since unit tests cover them or the sender cannot produce them | AMB-83, AMB-86 |
| 2026-10-27 | The sender CLI sends directly by default and goes through the broker only with `--via-broker`, so the sender works without the broker; the broker package is imported only then | AMB-84 |
| 2026-10-27 | `expected_folder` on `wait_for_link` / `wait_for_emails`, through `EmiApi` and the broker's `/wait`: an unreadable folder ends the wait at once with `READER_MAILBOX_EXPECTED_FOLDER_INACCESSIBLE` (environment); on the shared poller it ends only that wait; a folder that is not configured is a `ValueError` | AMB-85 |
| 2026-10-27 | Closed, not built: a connection per worker in `inprocess` mode (superseded by the shared poller), several accounts, a generated `docs/keywords.md`, the Gmail queue, and the remaining functional cases. The README's "Designed but Not Yet Implemented" section became part of "What Was Left Out" | AMB-86 |
