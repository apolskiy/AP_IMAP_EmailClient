| AMB-07 | **[EVIDENCE] Recipient filter semantics.** RFC 3501 `SEARCH TO` is a substring match, but Greenmail matched only the full address: a prefix search returned nothing. This works the same on substring servers and exact-match servers. | **Resolved 2026-10-26 (user), with refinements.**<br>• **Search mechanics** (service mode): on wait start, one `SEARCH TO "<address>"` finds pre-arrived mail; afterwards the service fetches only **new UIDs** (headers only) each poll cycle and dispatches them to waiting tests. `UIDVALIDITY` change → full re-search + log.<br>• **Recipient fields are selectable**: `match_fields`, **default `To` only**. Negative tests (a Bcc-only address must not match `To`-only searching) are realistic either way. |

| AMB-09 | **IMAP client library.** `imaplib` (stdlib), `imapclient`, or `aioimaplib`? | Medium | A) `imaplib` behind a small transport interface.<br>B) `imapclient` (nicer API, extra dependency).<br>C) `aioimaplib` (async). | **A.** No extra dependency, and it is synchronous, which fits pytest-xdist process parallelism. Caveat: `imaplib` wraps socket `OSError`s on send as `IMAP4.abort("socket error: …")`, which drops the errno. The wrapper must keep the original exception (`__context__`) so diagnostics can report it. A transport interface also makes fault injection in unit tests easy. | **Resolved 2026-10-26 (user): A**, on condition that advantages and disadvantages are documented (README "Design decisions").<br>**Advantages:** standard library (no dependency, maintained with CPython, nothing to install); speaks plain IMAP4rev1, so it works with any server, including Gmail and Greenmail; supports plain, SSL and STARTTLS; gives full control over commands (`UID FETCH`, `BODY.PEEK`, Gmail's `X-GM-RAW` if ever needed); synchronous, which fits pytest-xdist process parallelism and blocking test code.<br>**Disadvantages and mitigations:** a low-level API with raw byte responses, so we write our own small response parsing (covered by unit tests); socket errors are wrapped in `IMAP4.abort("socket error: …")`, which hides the errno, so the wrapper keeps the original exception for diagnostics; not thread-safe, so one lock per connection in the service; no pooling, retries or reconnects, so those are ours (AMB-13, AMB-47); folder names use modified UTF-7, which we encode ourselves; no async, which we do not need.<br>**Alternatives considered:** `imapclient` (friendlier parsing, but an extra dependency on top of `imaplib`); `aioimaplib` (async, mismatched with synchronous tests). |
